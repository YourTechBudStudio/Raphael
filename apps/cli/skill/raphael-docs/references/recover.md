# Recover

Choose the next step from the exit code. With `--json`, the error document on stderr also carries `code`, `applied` and `retryable`; a stderr line starting with `hint:` is a runnable next step.

| Exit | Meaning                                                 | Next step                                                                                                                                                                                                                                                                                                       |
| ---- | ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2    | The command as typed can never succeed; nothing applied | Fix it from the message and hint, or from `raphael help <command>`                                                                                                                                                                                                                                              |
| 3    | Not found                                               | The path may have moved: find the item by search or `raphael path --id <id>`, then retry                                                                                                                                                                                                                        |
| 4    | Conflicts with stored state; nothing applied            | `revision_conflict`: read again and reapply ([Change](change.md)). `slug_conflict`: choose another slug or restore the archived holder. `invalid_parent`: pick a parent that can hold the type and is not inside the item. `node_archived`: restore it or move it to an active parent ([Organize](organize.md)) |
| 5    | Not configured or not authorized                        | [Setup](setup.md)                                                                                                                                                                                                                                                                                               |
| 6    | Not applied; retrying may work                          | Retry once after a short pause, then report                                                                                                                                                                                                                                                                     |
| 7    | A write was sent and the outcome is unknown             | Read the target before anything else, the intended path for a create, and retry only if the change is absent                                                                                                                                                                                                    |
| 1    | Failed for another reason                               | Report the error; `RAPHAEL_DEBUG=1` adds a diagnostic stack                                                                                                                                                                                                                                                     |

After exit 7, or an interrupt during a write, a blind retry can apply the change twice; a retried create may even collide with the item the first attempt made. Tell the user plainly what happened, including when a change may or may not have been applied.

Details: `raphael help exit-codes` lists every code, and `raphael help output` describes the error document.
