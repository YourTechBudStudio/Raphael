# Documentation

Raphael's documentation separates product intent, architecture, extension contracts, decision rationale, and engineering guidance. Product and architecture descriptions express intended behavior and agreed boundaries, not a claim that the features are implemented.

## Understand the product

Start with [Product](./product/README.md) for Raphael's purpose, organizational model, and the relationship between captured thoughts and externally managed work.

## Understand the architecture

Read [Architecture](./architecture/README.md) for conceptual system boundaries, entity relationships, and operation ownership. These documents do not prescribe implementation mechanisms.

## Understand decisions

[Architecture decision records](./adrs/README.md) explain the authority decisions behind retrieval and search, mutations, and archive/restore. Use them for rationale and consequences rather than as an implementation guide.

## Work with extensions

Read [Extensions](./extensions/README.md) for the trust model, optional capabilities, author responsibilities, and hook behavior. These are conceptual contracts, not a finished SDK or installation guide.

## Apply engineering guidance

[Engineering guidance](./engineering-guidance/README.md) provides questions for designing and reviewing changes. It is not the product specification or a record of architectural commitments. Follow its own reading order when doing engineering work.
